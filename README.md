# Soloveyko.ai Video Maker

Десктопна програма для автоматизованого створення відео: переклад сценарію, озвучка, генерація відеоряду, субтитри та монтаж — все в одному пайплайні. Побудована на Rust + egui, кросплатформена (Windows / macOS).

---

## Архітектура

**Стек:** Rust + [eframe](https://github.com/emilk/egui/tree/master/crates/eframe) (egui). Один головний потік UI, всі мережеві запити виконуються у окремих `std::thread::spawn` потоках та повертають результат через `Arc<Mutex<Option<T>>>` + `ctx.request_repaint()`. Для обмеження паралельних запитів до API OpenRouter використовується потокобезпечний глобальний лімітер (семафор), що запобігає перевищенню лімітів та перевантаженню з'єднань.

**State management:** Весь стан програми живе у єдиній структурі `VideoMakerApp` (`src/app.rs`). Немає глобальних змінних. Налаштування автоматично персистяться у JSON-файл при кожній зміні (але тільки коли миша відпущена — щоб не бомбардувати диск під час перетягування бічної панелі).

**Два режими відображення:** вкладка `Main` (редактор + панель пайплайну) та вкладка `Settings` (тема, мова, колір акценту).

**Розділення відповідальностей:**
- `api/` — тонкі обгортки для зовнішніх сервісів (перевірка балансу, ключів)
- `core/pipeline/` — бізнес-логіка кожного етапу пайплайну (HTTP виклик + збереження файлу + статус задачі)
- `gui/pipeline/` — тільки UI-компоненти панелі пайплайну

## Ключові компоненти

### `VideoMakerApp` (`src/app.rs`)

Центральна структура. Реалізує `eframe::App`, тобто метод `update()` — головний loop рендерингу.

- **Баланс-чіпи в топбарі та налаштування лімітів:** при кліку на будь-який чіп відкривається вікно `draw_balance_window`. Чіпи відображаються тільки якщо баланс вже завантажений (не `None`). VoiceBot показує лише перше слово балансу (числове значення), щоб не займати місце. У цьому ж вікні інтегровано повзунок `egui::Slider` (від 1 до 25) для регулювання `openrouter_max_threads`. Будь-яка зміна повзунка миттєво оновлює глобальний лімітер запитів та автозберігається на диск.
- **Автозбереження:** в кінці `update()` порівнюється поточний стан з `last_saved_settings`. Якщо щось змінилось і миша відпущена (`!pointer.any_down()`) — файл перезаписується. Дельта для `translation_temperature`: > 0.001 (щоб уникнути зайвих записів під час перетягування повзунка).
- **Баланси завантажуються при старті:** якщо в налаштуваннях вже є ключі — виклик `fetch_balance` відбувається в `VideoMakerApp::new()`. OpenRouter перевіряється тільки якщо ключ починається з `sk-or-`.
- **Ширина панелі пайплайну:** egui зберігає ширину через `egui::Memory` між сесіями автоматично. `default_width` передається лише при першому запуску програми — далі егуі управляє шириною сам.
- **Нижня панель черги:** `TopBottomPanel::bottom("queue_panel")` з'являється тільки якщо `self.jobs` не порожній. Задачі відображаються горизонтально через `ScrollArea::horizontal`. Кнопка "▶ Запустити" активна лише якщо є задачі зі статусом `Pending` — при кліку запускає їх усі паралельно (кожна у своєму `std::thread::spawn`).
- **`job_name_dialog_open` / `job_name_input`** — стан діалогового вікна назви задачі. Ephemeral, не зберігається у `settings.json`.

### Черга задач (`src/queue.rs`)

- **`JobSettings`** — знімок усіх налаштувань пайплайну на момент додавання задачі. Зберігається в `PipelineJob` для можливого майбутнього перезапуску.
- **`JobStatus`** — `Pending → Running → Done / Failed(String)`. Обгорнутий у `Arc<Mutex<T>>`, бо змінюється з фонового потоку.
- **`PipelineJob::name`** — назва задачі, яку вводить користувач у діалозі. Якщо поле пусте — автоматично генерується як "Задача N" (де N = `jobs.len() + 1` на момент додавання).
- **Двоетапний workflow:** додавання задачі (`Pending`) і запуск (`Running`) — два окремі дії. Користувач може накопичити кілька задач у черзі і потім запустити їх усі кнопкою "▶ Запустити".

### Панель пайплайну (`src/gui/pipeline/mod.rs`)

Права бічна панель з 8 секціями у порядку: Шаблони → Шлях збереження → АПІ → Переклад → Озвучка → Відеоряд → Субтитри → Монтаж.

- **Секції "Переклад", "Озвучка", "Відеоряд", "Субтитри", "Монтаж"** мають toggle-перемикач (`toggle_switch`) прямо в заголовку. Стан перемикача відображається плавною анімацією через `animate_bool_responsive`.
- **Форма шаблону** завжди видима поза `ScrollArea` — навмисно, щоб не ховалась при скролі. Кнопка "Додати в чергу" також зафіксована внизу панелі.
- **ScrollArea обмежена по висоті** (`max_height = available_height - bottom_reserve`) — щоб залишити місце для кнопки та помилки внизу.
- **Всі секції** реалізовані через `CollapsingState` з persist id — egui запам'ятовує чи розкрита секція між кадрами.
- **Кнопка "Додати в чергу":** спочатку валідує поля (текст, шлях, модель, ключ). Якщо все ок — відкриває `egui::Window` з полем для введення назви задачі. Вікно по центру екрана, підтримує `Enter` для підтвердження.
- **`validate_and_enqueue`** — більше НЕ запускає обробку. Тільки створює папку `{save_path}/{task_name}/` через `std::fs::create_dir_all` і додає `PipelineJob` зі статусом `Pending`. Реальний запуск — через кнопку "▶ Запустити" в панелі черги.

### Етап перекладу (`src/core/pipeline/translate/`)

- **`mod.rs` — оркестрація:** spawns thread, виставляє статус `Running`, викликає `translate::call_openrouter`, при успіху зберігає результат у `{save_path}/text.txt` (папка вже існує — створена при додаванні задачі), виставляє `Done` або `Failed`.
- **`translate.rs` — HTTP виклик:** чиста функція `call_openrouter(key, model, user_content, temperature) -> Result<String>`. Не знає нічого про статуси, файли чи UI.
- **Плейсхолдер `{{text}}`:** якщо промт містить `{{text}}` — текст підставляється на місце. Якщо промт є але без плейсхолдера — текст додається після промту через `\n\n`. Якщо промт порожній — надсилається тільки текст.

### Збереження налаштувань (`src/gui/settings/storage.rs`)

Два JSON-файли зберігаються у `<UserConfigDir>/Soloveyko.AI-Video.Maker/`:
- `settings.json` — `AppSettings`: весь стан програми (тема, ключі, ширина панелі, стан пайплайну тощо).
- `templates/<name>.json` — `PipelineTemplate`: набір налаштувань пайплайну для швидкого перемикання між конфігами.

`AppSettings` та `PipelineTemplate` мають `#[serde(default)]`, тому старі файли без нових полів не ламаються.

### API-сервіси (`src/api/`)

Тільки утилітарні запити (баланс, перевірка ключа). Всі запити — синхронні `ureq`, загорнуті в `std::thread::spawn`. Результат пишеться у `Arc<Mutex<Option<T>>>`, після чого `ctx.request_repaint()` ініціює перемальовування UI.

- **Глобальне лімітування запитів OpenRouter (`OpenRouterLimiter`):**
  Потокобезпечний лімітер (семафор на базі `Mutex` та `Condvar` зі стандартної бібліотеки Rust) обмежує кількість одночасних запитів до OpenRouter по всій програмі.
  - Метод `acquire()` блокує потік, якщо досягнуто ліміту активних запитів, повертаючи `OpenRouterPermit<'a>`.
  - Завдяки реалізації трейту `Drop` для `OpenRouterPermit`, ліміт автоматично звільняється (викликається `release()`) при виході з області видимості, надійно запобігаючи витокам дозволів.
  - Лімітер інтегрований у перевірку балансу (`fetch_balance`), безпосередній переклад сценарію (`call_openrouter`) та фонове завантаження моделей.

| Сервіс | Ендпоінт | Що повертає |
|---|---|---|
| **OpenRouter** | `openrouter.ai/api/v1/credits` | Залишок кредитів: `$X.XX` |
| **VoiceBot** | `voiceapi.csv666.ru/balance` | `balance_text` — рядок з кількістю символів |
| **Googler** | `googler.fast-gen.ai/api/v3/account/usage` | `GooglerBalance`: img/video used+limit, threads active+allowed |

**НО — Googler `account_limits`:** поля лімітів можуть бути або числом, або об'єктом з ключем `used`/`count`/`current_usage`. Функція `extract_i64()` обробляє обидва формати, бо API Googler непостійний у структурі відповіді.

## API Інтеграції

| Сервіс | Призначення | Авторизація | Де налаштовується |

## Важливі нюанси та НО

- **Блокування на рівні `OpenRouterLimiter` не впливає на GUI-потік.** Оскільки всі мережеві виклики, які захищені лімітером (переклад сценарію, фонове завантаження моделей, перевірка балансу), виконуються у фонових потоках (`std::thread::spawn`), будь-яке блокування потоку семафором під час очікування вільного слоту відбувається непомітно для користувача і не спричиняє зависань інтерфейсу.

- **`googler_key` не входить у `PipelineTemplate`.** Ключ Googler зберігається тільки в `AppSettings` (глобальні налаштування), а не в шаблонах пайплайну. OpenRouter ключ — входить у шаблон. Така асиметрія є свідомою: шаблон — це конфіг пайплайну, а не конфіг акаунту.

- **Баланс-чіп VoiceBot** показує лише перше слово (число) з `balance_text`, щоб не займати місце в топбарі. Повний текст видно у вікні балансів.

- **Googler-баланс у топбарі** відображає 8 значень в одному рядку (`img: X/Y vid: X/Y th: X/Y X/Y`). Це компромісне рішення — детальне вікно балансів показує те саме у читабельному вигляді (grid-таблиця).

- **`windows_subsystem = "windows"`** у `main.rs` — приховує консоль у release-білді на Windows. У debug-режимі консоль є.

- **egui перемальовує весь фрейм щоразу** — тому будь-яка зміна стану одразу видна. Немає event-системи: якщо значення змінилось до наступного `update()`, воно одразу відобразиться.

- **`translation_model_search`** — ephemeral-стан (рядок пошуку у дропдауні), не зберігається у `settings.json` та не входить у шаблон. Скидається при запуску.

- **Повзунок температури (`translation_temperature`)** — ширина Slider в egui не контролюється через `add_sized`, а лише через `ui.style_mut().spacing.slider_width`. Тому перед рендерингом зчитується `ui.available_width()` і встановлюється у `scope`, щоб не забруднювати стиль батьківського `ui`.

- **Ширина елементів у `ui.horizontal()`:** egui автоматично додає `item_spacing.x` між кожною парою елементів. При розрахунку ширини першого елемента треба відіймати саме `ui.spacing().item_spacing.x`, а не довільне число — інакше рядок виходить ширший за available і SidePanel розповзається.

- **Секції "Субтитри" та "Монтаж"** поки порожні (заглушки). Їх наявність у пайплайні — місце під майбутню функціональність.

- **Шлях збереження задачі** — не сам `save_path`, а `{save_path}/{task_name}/`. Папка створюється при додаванні задачі в чергу (в `validate_and_enqueue`), а не при запуску. Якщо `create_dir_all` падає — задача не додається, показується помилка.

- **Діалог назви задачі** (`egui::Window`) рендериться всередині `draw_pipeline_panel`, але egui::Window завжди малюється поверх усього контексту — не прив'язується до SidePanel. Авто-назва ("Задача N") рахує `jobs.len()` на момент натискання "Додати", тому якщо додати дві задачі одночасно і залишити обидві без назви — отримаємо "Задача 1" і "Задача 2" послідовно.

## Локалізація

Всі UI-рядки — у `src/localization/{uk,en,ru}.rs`. Ключ додається у всі три файли одночасно. Якщо ключ відсутній — `translate()` повертає порожній рядок `""` (матч `_ => ""`).

Структура: `translate(language: Language, key: &str) -> &'static str`.
