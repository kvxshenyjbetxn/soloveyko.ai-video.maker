# 🔴 Skill: Завершення сесії (End Wiki)

## 🎯 Мета
Фіналізувати всі зміни в wiki, переконатися що документація актуальна, створити фінальний комміт. Використовується коли задача **повністю завершена**.

## 📋 Кроки (виконувати СТРОГО по порядку)

### Частина 1: Збір контексту з сесійного щоденника

1. **Використай свій сесійний щоденник** як основне джерело:
   - Усі дії за сесію (що робив, чому, які результати).
   - Усі прийняті рішення.
   - Усі проблеми та відкладені задачі.
2. **Перевір через git diff** — чи збігається з щоденником. Якщо є розбіжності — уточни.

### Частина 2: Перевірка та оновлення документації

3. **Перевір `.wiki/architecture.md`**:
   - Чи відображає фінальний стан структури проєкту?
   - Чи всі нові компоненти/модулі задокументовані?
   - Онови на основі сесійного щоденника.
   - Нові секції додавати **перед `<!-- ARCHITECTURE_END -->`**.

4. **Перевір `.wiki/decisions.md`**:
   - Чи всі рішення з сесійного щоденника зафіксовані?
   - Нові записи — **після `<!-- NEW_DECISION_ENTRY -->`** (зверху!).

5. **Перевір `.wiki/index.md`**:
   - Чи всі `[[WikiLinks]]` вказують на існуючі файли?
   - Якщо є мертві посилання — виправ або видали.

### Частина 3: Підсумковий запис

6. **Додай фінальний запис у `.wiki/log.md`**:
   - Місце: **після маркера `<!-- NEW_LOG_ENTRY -->`** (зверху!).
   - **Пиши на основі сесійного щоденника** — опиши що робилося, чому, які результати. Не просто перелік diff.
   - Формат:
     ```
     ## [YYYY-MM-DD] | Назва завершеної задачі
     - **Задача**: Що робилося (з якого контексту).
     - **Зміни**: Підсумок усіх змін (з сесійного щоденника).
     - **Файли**: [[файл1]], [[файл2]].
     - **Статус**: ✅ Завершено.
     - **Результат**: Що досягнуто.
     ```
   - **НЕ додавай в кінець файлу!**

### Частина 4: Фінальний комміт

7. **Сформуй фінальний комміт-меседж на основі сесійного щоденника**:
   - Що робилося, чому, які результати (не просто "змінено файл X").
   - Тип за стандартом **Conventional Commits**.
   - **Мова: УКРАЇНСЬКА** — обов'язково.
8. **Перевір через git diff** — чи відповідає меседж реальним змінам.
9. **Покажи комміт-меседж користувачу**. Якщо авто-режим — виконай комміт.

### Частина 5: Завершення

10. **Повідом користувача** українською: "Сесію завершено. Усе задокументовано та зафіксовано."

## ✅ Результат
- Усі wiki-файли актуальні.
- `log.md` містить фінальний запис зі статусом "✅ Завершено" на основі сесійного щоденника.
- Комміт створено (або меседж запропоновано).
- Жодних мертвих посилань у `index.md`.

## 🚫 Заборони
- Не формуй лог/комміт лише на основі git diff — основне джерело сесійний щоденник.
- Не додавай записи в кінець `log.md` — тільки після маркера зверху.
- Не залишай мертві `[[WikiLinks]]` — перевір кожне посилання.
- Не пропускай перевірку `architecture.md` — навіть якщо здається, що нічого не змінилося.
- Не позначай статус як "🟡 В процесі" — це фінал, статус "✅ Завершено".
