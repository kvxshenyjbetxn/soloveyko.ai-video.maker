# 🟡 Skill: Чекпоінт (Checkpoint Wiki)

## 🎯 Мета
Зберегти поточний прогрес у wiki та підготувати комміт, **не завершуючи** роботу. Використовується коли треба зафіксувати стан, але задача ще триває.

## 📋 Кроки (виконувати СТРОГО по порядку)

### Частина 1: Збір контексту з сесійного щоденника

1. **Використай свій сесійний щоденник** як основне джерело інформації:
   - Яку задачу виконував.
   - Що конкретно зробив (кожна дія).
   - Які файли змінено/створено.
   - Які рішення прийнято.
   - Що не вийшло / відкладено.

2. **Перевір через git diff** — чи збігається diff з тим, що ти записав у щоденнику. Якщо є розбіжності — уточни.

### Частина 2: Фіксація прогресу

3. **Додай запис у `.wiki/log.md`**:
   - Місце: **після маркера `<!-- NEW_LOG_ENTRY -->`** (зверху файлу!).
   - **Пиши на основі сесійного щоденника**, а не голого diff. Опиши ЩО ти робив і ЗАЩО, а не просто "змінено файл X".
   - Формат:
     ```
     ## [YYYY-MM-DD] | Коротка назва задачі
     - **Задача**: Що робилося (з якогось це контексту).
     - **Зміни**: Що конкретно змінено (з сесійного щоденника).
     - **Файли**: [[файл1]], [[файл2]].
     - **Статус**: 🟡 В процесі (чекпоінт).
     - **Результат**: Що досягнуто на даний момент.
     ```
   - **НЕ додавай в кінець файлу!**

4. **Якщо були прийняті технічні рішення** — зафіксуй у `.wiki/decisions.md`:
   - Місце: **після маркера `<!-- NEW_DECISION_ENTRY -->`** (зверху!).
   - Пиши чому прийнято рішення — це з сесійного щоденника.

5. **Якщо змінилася структура проєкту** — онови `.wiki/architecture.md`.

### Частина 3: Комміт-меседж

6. **Сформуй комміт-меседж на основі сесійного щоденника**:
   - Що саме робилося і чому (не просто перелік файлів).
   - Тип за стандартом **Conventional Commits** (feat, fix, docs, refactor, wiki тощо).
   - **Мова: УКРАЇНСЬКА** — обов'язково.
7. **Перевір через git diff** — чи відповідає меседж реальним змінам.
8. **Покажи комміт-меседж користувачу**. Якщо увімкнено авто-режим — виконай комміт.

### Частина 4: Підтвердження

9. **Повідом користувача** українською: "Прогрес зафіксовано (чекпоінт). Робота триває."
10. **Продовжуй вести сесійний щоденник** — після чекпоінту він не обнуляється.

## ✅ Результат
- `log.md` містить запис з статусом "🟡 В процесі" на основі сесійного щоденника.
- Комміт створено (або меседж запропоновано).
- Користувач знає, що прогрес збережено.
- Сесійний щоденник продовжується.

## 🚫 Заборони
- Не формуй лог/комміт лише на основі git diff — основне джерело сесійний щоденник.
- Не додавай записи в кінець `log.md` або `decisions.md` — тільки після маркерів.
- Не видаляй HTML-маркери `<!-- ... -->`.
- Не позначай статус як "завершено" — це чекпоінт, робота триває.
- Не перезаписуй весь файл — використовуй точкове редагування.
- Не обнуляй сесійний щоденник після чекпоінту.
