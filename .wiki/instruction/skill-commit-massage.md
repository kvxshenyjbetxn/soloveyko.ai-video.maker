# 💬 Skill: Комміт-меседж (Commit Massage)

## 🎯 Мета
Сформувати комміт-меседж на основі **сесійного щоденника** (що агент реально робив) з перевіркою через git diff. Використовується окремо або як частина checkpoint/end.

## 📋 Кроки (виконувати СТРОГО по порядку)

1. **Використай сесійний щоденник як основне джерело**:
   - Яку задачу виконував.
   - Що конкретно зробив і чому.
   - Які результати.
   - Це головне — комміт має відображати ТВОЇ дії та їхній сенс, а не просто "файл X змінено".

2. **Перевір через git diff**:
   - Виконай `git diff` та/або `git diff --staged`.
   - Порівняй з сесійним щоденником — чи все збігається.
   - Якщо diff містить зміни яких не було у щоденнику — уточни.

3. **Проаналізуй контекст з `.wiki/log.md`** (якщо є):
   - Останні 3-5 записів — загальний напрямок роботи.
   - Допоможе сформувати змістовний меседж.

4. **Визнач тип комміту** за стандартом **Conventional Commits**:
   | Тип | Коли використовувати |
   |:---|:---|
   | `feat:` | Нова функціональність |
   | `fix:` | Виправлення багу |
   | `docs:` | Зміни в документації |
   | `refactor:` | Рефакторинг без зміни поведінки |
   | `style:` | Форматування, пробіли тощо |
   | `test:` | Додавання/зміна тестів |
   | `chore:` | Дрібні технічні зміни |
   | `wiki:` | Зміни в `.wiki/` |

5. **Сформуй меседж**:
   - Формат: `тип: короткий опис українською`
   - Якщо потрібно більше контексту — додай body через пустий рядок.
   - **Описуй ЩО зроблено і ЗАЩО**, а не просто ЯКІ файли змінено.
   - **Мова: УКРАЇНСЬКА (обов'язково!)**

6. **Покажи меседж користувачу**:
   - Надай готовий текст.
   - Якщо увімкнено авто-режим — виконай комміт.
   - Усі пояснення щодо комміту — також українською.

## Приклади

**Правильно** (на основі сесійного щоденника):
```
feat: додано систему автентифікації користувачів

- JWT токени для API — замість сесій, щоб підтримувати stateless архітектуру
- Middleware для перевірки авторизації на всіх захищених роутах
- Тести для login/logout ендпоінтів
```

**Неправильно** (на основі лише diff):
```
feat: оновлено auth.ts, middleware.ts, auth.test.ts
```

## ✅ Результат
- Комміт-меседж сформовано на основі сесійного щоденника.
- Меседж українською мовою.
- Меседж відображає суть дій та їхній контекст, а не просто перелік файлів.
- Git diff підтверджує відповідність.

## 🚫 Заборони
- Не формуй меседж лише на основі git diff — сесійний щоденник першоджерело.
- Не пиши комміт-меседж англійською.
- Не пиши занадто загальні меседжі на кшталт "обновления" або "fixes".
- Не пиши просто перелік файлів — описуй суть змін.
- Не включай у меседж конфіденційну інформацію.
