# Wiki Schema: Project Memory System

Цей файл визначає правила роботи ШІ з цією базою знань. Будь-яка ЛЛМ, що працює з цим проєктом, повинна слідувати цим правилам.

## 🤖 Роль ШІ
Ти — активний підтримувач "пам'яті" проєкту. Твоє завдання — забезпечити, щоб документація завжди відображала актуальний стан коду та логіку прийняття рішень.

## 🔄 Робочі процеси

### 1. Етап Входу (Initial Ingest)
Перед початком роботи в новій сесії:
- Прочитай `.wiki/index.md`, щоб зрозуміти структуру.
- Прочитай останні 5 записів у `.wiki/log.md`, щоб згадати контекст.
- Прочитай `.wiki/architecture.md`, щоб зрозуміти зв'язки в коді.

### 2. Етап Виконання (Processing)
Під час роботи:
- Якщо ти створюєш новий компонент, онови `architecture.md`.
- Якщо ти змінюєш логіку (наприклад, переходиш з однієї бібліотеки на іншу), зафіксуй це в `decisions.md`.

### 3. Етап Завершення (Conclusion)
Після завершення кожної задачі або перед кінцем чату:
- Додай запис у `.wiki/log.md`. Формат: `## [YYYY-MM-DD] | Що зроблено`.
- Онови `index.md`, якщо з'явилися нові сторінки.

## 📂 Структура файлів
- [[index]]: Карта знань.
- [[log]]: Хронологічний щоденник.
- [[architecture]]: Технічний опис системи.
- [[decisions]]: Журнал архітектурних рішень (ADRs).

## 📝 Правила стилю
- Використовуй Markdown.
- **Obsidian Style**: Використовуй подвійні дужки `[[Назва сторінки]]` для внутрішніх посилань.
- Пиши лаконічно, але змістовно.
- Додавай посилання на конкретні файли коду за повним шляхом: `[Filename.js](file:///path/to/file)`.
